\chapter{HTTP API: Endpoints, Events, and Errors}

The MCP server is the product surface; the HTTP API underneath it is what the Tottie UI,
the eval harness, and the seed script talk to. Every route requires the Bearer [REDACTED]
except \texttt{GET /health}. All \texttt{POST} bodies are JSON; all times are ISO-8601.

\section{Request and Response Shapes}
\texttt{POST /write}: \texttt{\{text, session\_id, turn, owner, source:\{trust\}\}}
$\rightarrow$ \texttt{202 \{event\_id\}}. The idempotency key
\texttt{hash(session, turn, content)} is computed server-side; retries return the same
\texttt{event\_id} without double-writing (unique index on \texttt{(owner, hash)}).

\texttt{POST /recall}: \texttt{\{query, session\_id, owner, tiers?, k?\}}
$\rightarrow$ \texttt{\{card, hits:[\{id, tier, kind, summary, tags, score, trust, why\}],
confidence, abstain, mode, cue, margin, path, candidates\_matched, timeline?,
fired\_intentions, registered\_intention, latency\_ms\}}.
The \texttt{why} line per hit is the ``why this surfaced'' annotation; \texttt{fired\_intentions}
carries any prospective intentions this turn triggered; \texttt{mode} is \texttt{ranked} or
\texttt{replay} (recency cues bypass ranking for ordered session replay). Verified W2: 32~ms
over a 100-row store, 10$\times$ inside the 300~ms p95 budget.

\texttt{GET /probe?tag=\&owner=} $\rightarrow$ the room's live, non-quarantined
memories, most salient first (a read, so \texttt{GET} like \texttt{/identity}).

\texttt{POST /intend}: \texttt{\{content, owner, event\_cue?, time\_cue?\}} $\rightarrow$
\texttt{201 \{id\}}. At least one cue is required.

\texttt{POST /consolidate}: \texttt{\{owner, replay\_n?\}} $\rightarrow$
\texttt{\{episodic\_replayed, semantic\_written, ranked\_out, curated\}}.

\texttt{POST /memories/\{id\}/confirm}: flips \texttt{quarantined} to false, raises trust to
\texttt{user\_direct}, and writes an audit event. Only the owning user can confirm.

\texttt{POST /forget}: \texttt{\{id|query, owner\}} $\rightarrow$ hard-deletes the rows,
their links, and their event rows, then writes an audit row proving it happened.

\texttt{GET /graph}: \texttt{?owner=\&session\_id?(\&tiers?)} $\rightarrow$
\texttt{\{nodes:[\{id, label, tier, tags, salience, created\}], links:[\{source, target,
relation, weight\}]\}}, capped at $\approx$300 nodes (most salient first). The recall response
additionally carries \texttt{path:[ids]} --- the ordered node ids of the retrieval chain --- plus
\texttt{candidates\_matched} and the distinctiveness margin, so the Panel can narrate the story
and the brain graph can light the path.

\section{The Event Stream}
\texttt{GET /events?session\_id=\&last\_event\_id=\&token=} streams \texttt{memory\_event}
rows as Server-Sent Events with the row's monotonic \texttt{id} as the event id. EventSource
cannot set headers, so \texttt{/events} takes the bearer token as a query param (localhost demo;
the token is never logged). A reconnecting Panel passes \texttt{Last-Event-ID} (or the query
param) and the server replays everything after it, so no step is ever missed. The server assigns
the monotonic \texttt{event\_id} (the client's \texttt{turn} is echoed for correlation only);
chat and Panel both render from it, so they can never disagree. Test-harness trap, verified W1:
httpx 0.28's \texttt{ASGITransport} awaits the \emph{entire} app call before returning, so an
infinite SSE stream can never deliver a byte through it --- the test hung on a route that works.
The suite therefore drives the live app by direct ASGI invocation with manual send/receive
queues: real routing, auth, framing, DB, and resume, with disconnect asserting the stream ends
instead of leaking.

\section{Errors}
\texttt{401} without (or with a wrong) token. \texttt{422} on schema violations (with the
failing field named). \texttt{429} past the per-owner rate limit (60 writes/min, 2000
rows/day). \texttt{503} with \texttt{\{retryable:true\}} when the embedder or the pool is
unhealthy --- the UI shows ``memory unavailable'' and the host falls back to raw model.
Low confidence is \emph{not} an error: it returns \texttt{200} with
\texttt{confidence} below \texttt{0.35} and an explicit \texttt{abstain:true} recommendation.

\section{Cross-Origin and Health}
The UI (\texttt{:3055}) calls the core (\texttt{:8765}) directly, so the core serves CORS for
the configured UI origin only. \texttt{GET /health} returns
\texttt{\{pool, queue\_depth, embedder:\{loaded, model\}, providers:\{mode, meta, local, active\}\}}
and is the readiness gate for the demo and the harness: if \texttt{embedder.loaded} is false,
nothing else is attempted. \texttt{active} is probe-verified, so it is \texttt{null} when the
pinned provider is down rather than echoing the pin.
