\chapter{HTTP API: Endpoints, Events, and Errors}

The MCP server is the product surface; the HTTP API underneath it is what the Tottie UI,
the eval harness, and the seed script talk to. Every route requires the Bearer [REDACTED]
except \texttt{GET /health}. All \texttt{POST} bodies are JSON; all times are ISO-8601.

\section{Request and Response Shapes}
\texttt{POST /write}: \texttt{\{text, session\_id, turn, owner, source:\{trust\}\}}
$\rightarrow$ \texttt{202 \{event\_id\}}. The idempotency key
\texttt{hash(session, turn, content)} is computed server-side; retries return the same
\texttt{event\_id} without double-writing (unique index on \texttt{(owner, hash)}).

\texttt{POST /recall}: \texttt{\{query, session\_id, owner, tiers?, k?\}}
$\rightarrow$ \texttt{\{card, hits:[\{id, tier, kind, summary, tags, score, trust, why\}],
clusters:[\{label, ids, size\}], confidence, abstain, mode, cue, margin, path,
candidates\_matched, timeline?, fired\_intentions, registered\_intention, latency\_ms\}}.
The \texttt{why} line per hit is the ``why this surfaced'' annotation;
\texttt{clusters} is the rule Completer's tag-grouping of the hits (W5);
\texttt{fired\_intentions} carries any prospective intentions this turn triggered;
\texttt{mode} is \texttt{ranked} or \texttt{replay} (recency cues bypass ranking for
ordered session replay). Verified W2: 32~ms over a 100-row store, 10$\times$ inside
the 300~ms p95 budget.

\texttt{GET /probe?tag=\&owner=} $\rightarrow$ the room's live memories, most salient
first, ranked-out \emph{included} (the revival path) and quarantined excluded
(a read, so \texttt{GET} like \texttt{/identity}).

\texttt{POST /chat}: \texttt{\{text, session\_id, owner?, memory=true\}} $\rightarrow$
\texttt{\{reply, card, confidence, abstain, path, hits, model, event\_id,
tokens:\{prompt, completion\}, latency\_ms\}}.
One demo turn with no history window (memory replaces context stuffing): recall the card,
inject any fired intentions as a ``reminders due'' block, answer grounded in it, enqueue
the user turn. \texttt{memory=false} is the ablation OFF arm
(raw model, no recall, no write). Replies are never written.

\texttt{POST /v1/chat/completions}: \texttt{\{messages, model?, stream?, temperature?\}} $\rightarrow$ standard OpenAI wire format (\texttt{\{id, object: "chat.completion", created, model, choices:[\{index:0, message:\{role:"assistant", content\}, finish\_reason:"stop"\}], usage\}}).
Acts as a transparent reverse proxy between arbitrary agent hosts (Muse, Cursor, Continue, LangChain) and the underlying LLM provider.
On arrival, the route:
\begin{enumerate}
  \item Intercepts the terminal user utterance from \texttt{messages[-1]}.
  \item Auto-probes and pairs the calling proxy agent in the presence ledger without manual pairing gates.
  \item Automatically executes associative recall via \texttt{retrieve.recall()}, formulating a Context Card with confidence annotations.
  \item Injects the synthesized Context Card directly into the system message of the active prompt payload.
  \item Forwards the enhanced payload to the resolved model provider (Meta Muse Spark or local Ollama).
  \item Returns standard compliant chat completions JSON or Server-Sent Events text-stream chunks to the caller.
  \item Asynchronously enqueues the turn to the \texttt{WriteQueue} (\texttt{curate\_turn}), allowing the Observer and Scribe to assess surprise and broadcast node creations to the real-time 3D graph view via SSE within the calibrated latency window.
\end{enumerate}

\texttt{GET /v1/models}: $\rightarrow$ standard OpenAI models list (\texttt{\{object:"list", data:[\{id:"muse-spark-1.3-contributor", object:"model"\}]\}}) to satisfy client handshake requirements.

\texttt{GET /memories?owner=\&quarantined?\&kind?\&id?\&limit=} $\rightarrow$ live rows newest
first (the pending strip reads \texttt{quarantined=true}; node detail reads by \texttt{id}).

\texttt{GET /graph?owner=\&tiers=} $\rightarrow$ \texttt{\{nodes:[\{id, label, tier, tags,
salience, created, quarantined\}], links:[\{source, target, relation, weight\}]\}}, capped at
300 most-salient live rows (links restricted to the returned node set).

Prospective registration has no HTTP route: the \texttt{memory.intend} MCP tool plus
automatic registration of ``remind me\ldots'' turns on both the write path (Scribe, W5)
and the recall path (\texttt{COMMAND} cue). Registration is idempotent on pending content.

\texttt{POST /consolidate}: \texttt{\{session\_id, owner?\}} $\rightarrow$
\texttt{\{episodes\_replayed, semantic\_written, semantic\_ids, semantic\_error,
ranked\_out, links\_decayed, tokens\}} (W5, plus a \texttt{CONSOLIDATE} ledger event).
Sleep degrades, never dies: if the LLM semanticise step fails, rank + decay still run
and the summary carries \texttt{semantic\_error}.

\texttt{POST /briefing}: \texttt{\{session\_id, owner?, text?, since\_event\_id?\}}
$\rightarrow$ \texttt{\{briefing, card, confidence, abstain, fired\_intentions, new\_items,
event\_id\}}. The agent's once-per-turn call. No \texttt{text}: recall runs on the
session's own recent utterances (pure ambient). Due intentions (time dues need no entity
match) and memories formed since the cursor always flow, even when the card abstains.
\texttt{briefing} is pre-formatted for direct injection into agent context; the
\texttt{scripts/tottie.py brief} CLI wraps it.

\texttt{POST /memories/\{id\}/confirm}: flips \texttt{quarantined} to false, raises trust to
\texttt{user\_direct}, and writes an audit event. Only the owning user can confirm.

\texttt{POST /forget}: \texttt{\{id|query, owner\}} $\rightarrow$ hard-deletes the rows,
their links, and their event rows, then writes an audit row proving it happened.
By query it deletes the top-1 hit only when recall does not abstain; a vague query
\texttt{404}s rather than risk an innocent row.

\texttt{GET /graph}: \texttt{?owner=\&session\_id?(\&tiers?)} $\rightarrow$
\texttt{\{nodes:[\{id, label, tier, tags, salience, created\}], links:[\{source, target,
relation, weight\}]\}}, capped at $\approx$300 nodes (most salient first). The recall response
additionally carries \texttt{path:[ids]} --- the ordered node ids of the retrieval chain --- plus
\texttt{candidates\_matched} and the distinctiveness margin, so the Panel can narrate the story
and the brain graph can light the path.

\section{The Event Stream}
\texttt{GET /events?session\_id=\&last\_event\_id=\&token=} streams \texttt{memory\_event}
rows as Server-Sent Events with the row's monotonic \texttt{id} as the event id. EventSource
cannot set headers, so \texttt{/events} takes the bearer token as a query param (localhost demo;
the token is never logged). A reconnecting Panel passes \texttt{Last-Event-ID} (or the query
param) and the server replays everything after it, so no step is ever missed. The server assigns
the monotonic \texttt{event\_id} (the client's \texttt{turn} is echoed for correlation only);
chat and Panel both render from it, so they can never disagree. Test-harness trap, verified W1:
httpx 0.28's \texttt{ASGITransport} awaits the \emph{entire} app call before returning, so an
infinite SSE stream can never deliver a byte through it --- the test hung on a route that works.
The suite therefore drives the live app by direct ASGI invocation with manual send/receive
queues: real routing, auth, framing, DB, and resume, with disconnect asserting the stream ends
instead of leaking.

\section{Errors}
\texttt{401} without (or with a wrong) token. \texttt{422} on schema violations (with the
failing field named). \texttt{429} past the per-owner rate limit (60 writes/min, 2000
rows/day). \texttt{503} with \texttt{\{retryable:true\}} when the embedder or the pool is
unhealthy --- the UI shows ``memory unavailable'' and the host falls back to raw model.
Low confidence is \emph{not} an error: it returns \texttt{200} with
\texttt{confidence} below \texttt{0.35} and an explicit \texttt{abstain:true} recommendation.

\section{Cross-Origin and Health}
The UI (\texttt{:3055}) calls the core (\texttt{:8765}) directly, so the core serves CORS for
the configured UI origin only. \texttt{GET /health} returns
\texttt{\{pool, queue\_depth, embedder:\{loaded, model\}, providers:\{mode, meta, local, active\}\}}
and is the readiness gate for the demo and the harness: if \texttt{embedder.loaded} is false,
nothing else is attempted. \texttt{active} is probe-verified, so it is \texttt{null} when the
pinned provider is down rather than echoing the pin.
