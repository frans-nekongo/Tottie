\section{The Panel Is a Live Stream of \texttt{memory\_event}s}
The UI subscribes to \texttt{GET /events?session\_id=} (Server-Sent Events). Each event card shows
the four things that matter, in order:
\begin{enumerate}
  \item \textbf{What it is learning now} --- the turn plus the Observer verdict (KEEP/DISCARD,
  salience, reason).
  \item \textbf{What memories it is forming} --- the Scribe operation badge
  (\texttt{NEW} / \texttt{UPDATE} / \textbf{\texttt{SUPERSEDE}} / \texttt{SKIP}) and the memory text
  (superseded ones struck through).
  \item \textbf{Where it inserted them} --- the tier chip and the tag/room chips, plus a live
  \textbf{room map} that grows as new tags appear.
  \item \textbf{What it injected into context} --- the literal \textbf{Context Card} the Curator
  built for that turn, annotated with a \textbf{``why this surfaced''} line per hit
  (\texttt{cue=COMMAND $\rightarrow$ seed \#project/tottie $\rightarrow$ spread 1 hop (w=0.6)}). This
  is what makes the write-time \emph{and} the associative-retrieval decision visible on camera.
\end{enumerate}

\section{The Brain Graph (3D)}
The Panel's second hero: a rotatable 3D force graph of the memory store --- the ``brain'' the demo
is named for. Built on \textbf{react-force-graph-3d} (pinned version, dynamic import with
\texttt{ssr:false}; Three.js/WebGL rendering, d3-force-3d physics). Rotate, zoom, and node-drag
are built in; the physics loop runs outside React's render cycle and the UI only pushes data.
\begin{itemize}
  \item \textbf{Data:} \texttt{GET /graph} serves \texttt{\{nodes, links\}} from \texttt{memories} +
  \texttt{memory\_links} (cap $\approx$300 nodes, tier filter). SSE \texttt{NEW} events append a
  node live with a pulse; \texttt{SUPERSEDE} re-links the branch.
  \item \textbf{Mapping:} node colour by tier (identity gold, episodic cyan, knowledge violet,
  procedural green, prospective amber); node size by salience; link colour/width by relation and
  weight; curved links; hover shows a label sprite, click opens the memory detail.
  \item \textbf{The firing path:} each recall response carries ordered \texttt{path:[ids]}; the graph
  lights that chain and runs travelling particles along it (\texttt{linkDirectionalParticles} /
  \texttt{emitParticle}) while the story line narrates it.
  \item \textbf{The look:} bounded dark sphere, bloom via \texttt{postProcessingComposer}
  (UnrealBloomPass), dimmed non-path elements during a highlight. A glowing force-sphere with
  firing paths --- no literal brain mesh.
  \item \textbf{Fallback:} the 2D sibling shares the identical interface; if 3D misbehaves on film
  day the swap is one line, same data. No \texttt{@types} package exists for the graph
  library, so W4 ships a \texttt{ui/types/force-graph.d.ts} shim.
  \item \textbf{Build gates:} follows the web3d process inside W4 (test list, headless
  \texttt{check\_page} runs, screenshots, fresh-player critique) before it is allowed on camera.
\end{itemize}

\section{Physical Realtime Animation Mechanics and Birth Lifecycle}
To give the Architect immediate visual confirmation that Tottie is persistently learning without
requiring manual browser clicks, the 3D brain implements a physical drop-in animation lifecycle
driven by Server-Sent Events (\texttt{GET /events}) and rendered in WebGL via
\texttt{react-force-graph-3d}:

\begin{enumerate}
  \item \textbf{The Realtime Event Stream (\texttt{GET /events}):}
  The browser maintains an active EventSource connection to the Tottie backend with a 150\,ms live
  tail poll over PostgreSQL \texttt{memory\_events}. When the transparent proxy or an agent turn
  commits a new memory or supersedes an old one, the backend emits a named \texttt{event: memory} frame.
  \item \textbf{Avatar Reaction (\texttt{TottieFace}):}
  Upon receiving \texttt{op = NEW} or \texttt{SUPERSEDE}, \texttt{page.tsx} instantly calls
  \texttt{flash('remembering', 2200)}, switching the header SVG sprite from \texttt{idle} to the glowing
  \texttt{remembering} state.
  \item \textbf{Ephemeral Birth Feed Banner (\texttt{BirthFeed}):}
  A toast slides down in the top-right corner of the canvas displaying the exact operation chip
  (\texttt{[NEW]} or \texttt{[SUPERSEDE]}) along with the first 110 characters of the captured utterance,
  persisting for 12 seconds before decaying.
  \item \textbf{Sky Dock Pinning and Heat Curve (\texttt{GraphView.tsx}):}
  When new nodes are fetched via \texttt{GET /api/graph}, they are clocked with a birth timestamp.
  Over a generous window of $\tau_{\text{fresh}} = 3800\,\text{ms}$, the node's temperature scales via:
  \begin{equation}
    \text{heat}(t) = \max\left(0, 1 - \frac{t - t_{\text{born}}}{\tau_{\text{fresh}}}\right)
  \end{equation}
  \begin{itemize}
    \item \textbf{Incandescent Electric Cyan Birth:} The newborn node appears in brilliant glowing
    electric cyan (\texttt{\#00f0ff}) with high visual pop against the dark canvas, then smoothly
    interpolates into its permanent tier hue (identity gold, knowledge violet, procedural green)
    via $\text{mixHex}(\texttt{\#00f0ff}, \text{baseColor}, 1 - \text{heat})$.
    \item \textbf{Pop-Scale Expansion:} The physical node sphere scales up to $2.5\times$ its normal salience
    radius via $\text{popScale}(\text{heat}) = 1 + 1.2 \cdot \text{heat}^{1.5}$.
    \item \textbf{Sky Dock Gravitational Glide:} While $\text{heat} > 0.60$, the node's coordinates are pinned
    elevated above the main cluster using d3-force fixed pins ($fx, fy, fz = \text{spawnOf}(id)$).
    Once cooled below $0.60$, $fx, fy, fz$ are released, causing the node to gravitationally glide down into its
    semantic neighborhood.
    \item \textbf{Synaptic Particle Streams:} Edges connected to the newly arrived node shoot high-speed
    directional particles in glowing electric cyan (\texttt{\#00f0ff}) to visually depict associative wiring.
    \item \textbf{Living Neural Pulse (Zero Freeze):} When at rest, nodes never freeze in place. The animation loop
    continuously drives an organic harmonic breathing wave ($r(t) = r_0 \cdot [1 + 0.10 \sin(\omega t + \phi_i)]$)
    while OrbitControls gently revolves the 3D galaxy ($\text{autoRotateSpeed} = 0.45$), eliminating any stagnant
    look on screen.
  \end{itemize}
  \item \textbf{Automated Camera Flight (\texttt{flyToNew}):}
  The Three.js camera does not stay stationary. Within 250\,ms of newborn node adoption, the viewport
  smoothly glides over 800\,ms to center and focus directly on the live centroid of the newly arrived
  memory nodes at a friendly framing distance ($d \in [220, 600]$), ensuring the user never misses the
  birth drop-in even if zoomed elsewhere.
  \item \textbf{Tombstone Shrink-out on Supersede (\texttt{DIE\_MS = 700ms}):}
  When an existing memory is superseded (e.g. migrating frameworks or updating facts), the victim node is
  unlinked from the active cluster, turned into a pinned crimson ghost node (\texttt{\#d9534f}), scaled
  down linearly to zero over 700\,ms, and unmounted without resetting or reheating the force simulation.
\end{enumerate}

\section{The Sleep Button}
A single \textbf{Sleep} control runs the Consolidator on demand. During the run the Panel shows a
progress strip (\emph{``replaying N episodes\ldots''}) and then a summary
(\emph{``12 episodic $\rightarrow$ 3 semantic; 4 ranked out''}). It is the only control that shows
\emph{generalisation} happening. See \emph{Process Flows: Consolidation}.

\section{Tottie Avatar --- Drop-In Sprite (frame sets per state)}
\begin{itemize}
  \item \textbf{Built here:} a \texttt{TottieFace} component plus a state machine with five states
  --- \texttt{idle}, \texttt{listening}, \texttt{thinking}, \texttt{remembering}, \texttt{speaking}
  --- driven by app events (streaming tokens $\rightarrow$ \texttt{speaking}; a write event or a
  recall $\rightarrow$ \texttt{remembering}; the Sleep job $\rightarrow$ \texttt{remembering}).
  \item \textbf{Provided by the Architect:} frame sets in \texttt{ui/public/tottie/<state>/}. Drop
  PNGs; \textbf{no code change required}.
  \item \textbf{Contract:} \texttt{TottieFace} reads \texttt{\{state, framesDir, fps\}}. A
  placeholder frame set ships so the app runs before the final art lands.
  \item \textbf{No TTS / no lip-sync.} The sprite reacts to memory events; that is the whole job.
\end{itemize}

\section{Ablation Toggle}
A single \textbf{Tottie ON/OFF} switch. OFF = no card injected and no writes (raw model). ON = full
memory. Used live in the demo to prove that a correct answer \emph{depended on} memory rather than
on the base model.
