\chapter{Model Providers and the Intelligence Layer}

\section{Provider Abstraction}
All model calls go through one interface, so the demo can switch models without code changes:

\begin{Verbatim}[breaklines=true,fontsize=\small]
class LLMProvider:
    async def complete(self, messages, json_schema=None) -> str: ...
\end{Verbatim}

\begin{itemize}
  \item \textbf{MetaProvider} --- the Meta Model API (Muse Spark series). Configured by
  \texttt{META\_API\_KEY}, \texttt{META\_BASE\_URL}, \texttt{META\_MODEL}.
  \item \textbf{LocalProvider} --- an OpenAI-compatible local server (Ollama \texttt{:11434} or
  llama.cpp \texttt{:8080}), configured by \texttt{LOCAL\_LLM\_URL}, \texttt{LOCAL\_LLM\_MODEL}.
  \item \textbf{resolve\_provider()} --- uses Meta when a key is present and the endpoint is
  healthy, otherwise falls back to local. \textbf{The demo never dies on a provider outage.}
\end{itemize}

\section{Meta Depth (the rubric column)}
The demo routes the Observer/Scribe, the Consolidator, and the chat brain through the
\textbf{Meta Model API (Muse Spark series)} whenever \texttt{META\_API\_KEY} is set --- Meta is
the primary path, not a logo. The local fallback is a single configured model
(\texttt{LOCAL\_LLM\_MODEL}, default a Qwen coder via Ollama) --- API-first stands and the
open-weights bonus chase was CUT by locked decision R2, so no Meta-weights preference ordering
exists; adding one plus a Meta open-weights install is the documented path if the bonus is
pursued. Every eval run records the exact model ids, so a judge can see Meta in the loop rather
than taking it on faith.

\section{Verified Endpoint (2026-10-27)}
Live-verified against the real API: base URL \texttt{https://api.meta.ai/v1}, model
\texttt{muse-spark-1.3-contributor}, OpenAI-compatible Chat Completions (Responses and Messages
formats also accepted), Bearer-key auth. Three findings constrain the provider implementation:
(1) this is a \textbf{reasoning model} --- \texttt{max\_tokens} silently returns null content
with \texttt{finish\_reason: length}; the provider must send \texttt{max\_completion\_tokens};
(2) a trivial ``OK'' burned \textbf{116 reasoning tokens} ($\approx$5.3~s), so Observer/Scribe
extraction calls want the lowest reasoning effort the API allows or every write pays the tax;
(3) \texttt{temperature: 0} is accepted and stays mandatory for all curation calls;
(4) there is a \textbf{reasoning budget floor} --- \texttt{max\_completion\_tokens=64} ends
\texttt{finish=length} with empty content because hidden reasoning eats the whole budget (a
one-word reply costs $\approx$150 completion tokens). Budgets below $\approx$256 are unusable;
the smoke test pins 512 and the Observer uses 1024. The provider's empty-content error names
the cause so a too-small budget fails loud instead of looking like an outage.

\section{The Provider Switch (W1, verified)}
\texttt{TOTTIE\_PROVIDER=auto|meta|local} is read fresh on every resolve, so flipping the
variable switches the brain \textbf{with no restart}. \texttt{auto} probes Meta then local and
takes the first healthy one; pinned modes skip the probe and fail loud at use time; typos raise.
\texttt{GET /health} reports both the requested \texttt{mode} and the probe-verified
\texttt{active} provider --- a pin to a downed Ollama shows \texttt{mode=local, active=null},
never a fake ``local''.

\section{Cost Control}
Tottie's whole argument is that write-time curation is cheaper than stuffing context. The eval
harness measures \textbf{tokens per query} with memory ON vs OFF to make that claim falsifiable.

\section{Optional: MCP Sampling (flagged, off by default)}
MCP sampling (\texttt{ctx.session.create\_message}) would let the Observer/Scribe curate using the
\emph{host's} model, with \textbf{no server-side API key} --- an elegant ``surprised even us''
capability. Two caveats: it is \textbf{deprecated in the 2026-07-28 specification} (SEP-2577) in
favour of Multi Round-Trip Requests, and many hosts do not declare the capability. It is therefore
\textbf{flag-gated} (\texttt{TOTTIE\_USE\_SAMPLING=0} by default) and never the primary path.
