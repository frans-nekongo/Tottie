\chapter{MCP Surface}

Tottie ships as an MCP server over \textbf{stdio} (Python SDK, \texttt{mcp<2} with \texttt{FastMCP}).
The whole point is that the same memory mounts into any host: the Tottie chat, a VS Code / Cursor
agent, anything that speaks MCP. It imports the core in-process (no HTTP hop) and inherits
the core's auth: no token in env, no start (see \emph{Security}).

\section{Resources}
\begin{itemize}
  \item \texttt{memory://identity} --- the pinned persona/constraints.
  \item \texttt{memory://tag/\{tag\}} --- the contents of a room, readable without a tool call.
\end{itemize}

\section{Prompt}
\texttt{tottie\_context\_card} --- a reusable system-prompt fragment that teaches a host how to use
the memory correctly (when to trust the card, when to probe, when to abstain).

\section{Dual-Path Recall (the design answer)}
A common question is: ``does the retriever hand context to the agent, or does the agent probe for
it?'' Tottie does \textbf{both, deliberately}:
\begin{enumerate}
  \item \textbf{Ambient path} --- the Curator injects the Context Card automatically on every turn,
  so the agent ``just knows'' without issuing a query.
  \item \textbf{Deliberate path} --- the card carries \textbf{pointers} (tags/rooms); when the agent
  needs depth it calls \texttt{memory.probe(tag)} and reads that room.
\end{enumerate}

\section{Retrieval Is Cue-Typed, Not Just Similar}
The \texttt{memory.recall} tool does not run a single similarity search. It classifies the cue,
chooses a policy, seeds nodes, and spreads activation across \texttt{memory\_links}. See
\emph{The Cognition Model} for the full specification.

\section{Confidence in the Response}
Alongside the card, \texttt{memory.recall} returns a \textbf{confidence} derived from the retrieval
margin. A low-confidence result is an instruction to the host to verify or abstain rather than
assert --- the metacognitive gate.
