\chapter{Performance, Cost, and Resilience}

Memory must be \emph{invisible} in the hot path. This chapter records the budgets and the engineering
that keeps Tottie fast and cheap, and what happens when a model fails.

\section{The Non-Blocking Write Path}
An Observer model call on the critical path would add latency to every user turn. So the write path is
\textbf{decoupled}:

\texttt{POST /write} validates, computes an \textbf{idempotency key}, enqueues, and returns
\texttt{202 \{event\_id\}} in under 20 ms. The Panel receives the result later over SSE.

\section{Bounded Recall}
The read path has a hard wall-clock budget. Per-leg candidate caps (50), Reciprocal Rank Fusion with
$k=60$, a top-8 cut, a graph expansion of at most \textbf{2 hops} and \textbf{50 nodes} with a decay of
0.5, and a token-capped card. Nothing in recall is unbounded.

\section{Cost Control}
\begin{itemize}
  \item A \textbf{heuristic pre-filter} skips the model for obvious chit-chat and fast-paths clear
  patterns (``my \ldots'', ``always'', ``never'', a date).
  \item A \textbf{small model} handles the Observer; the strongest model is reserved for the brain.
  \item The \textbf{Observer and Scribe share one structured-output call} (temperature 0, JSON
  schema): propose candidates and structure them in the same pass.
  \item The 400-token card budget is measured with a \textbf{chars/4 heuristic} --- no tokenizer
  dependency; close enough for a budget, and it never fails.
  \item Identical turns are cached; token caps are enforced on every call.
\end{itemize}

\section{Storage Engineering}
\begin{itemize}
  \item \textbf{Connection pooling} (psycopg \texttt{AsyncConnectionPool} created at startup)
  instead of a connection per request.
  \item The embedder is \textbf{loaded once} and all embedding calls run in a thread pool, so the
  synchronous ONNX call never blocks the event loop.
  \item \textbf{HNSW} indexes are built with explicit \texttt{m = 16} / \texttt{ef\_construction = 64}
  and queried with \texttt{hnsw.ef\_search = 100} plus \texttt{hnsw.iterative\_scan = strict\_order}
  (requires pgvector $\geq$ 0.8), which keeps walking the graph until enough rows pass the filter.
  The \textbf{over-fetch} (top-50 per leg) before filtering by owner and validity stays as
  belt-and-braces.
\end{itemize}

\section{Resilience}
\begin{itemize}
  \item \textbf{Idempotency:} a hash of \texttt{(session, turn, content)} prevents duplicate writes on
  retry.
  \item \textbf{Raw fallback:} if the Observer or Scribe fails, the turn is written as a raw episodic
  row with \texttt{needs\_curation = true}; the Consolidator curates it later. A model outage must
  never lose data.
  \item \textbf{Backpressure:} a bounded queue with a drop-oldest policy and a metric when it trips.
  \item \textbf{Reconcile locking:} a partial unique index on
  \texttt{(owner, subject, predicate) WHERE valid\_to IS NULL} serialises contradicting writes.
\end{itemize}

\section{Observability}
Metrics: write and recall latency, tokens per call, queue depth, the surprise and confidence
distributions, hit rate, and the ranked-out count. Structured logs carry a request id.
