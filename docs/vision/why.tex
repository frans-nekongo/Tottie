\chapter{Why Tottie Exists}

\section{The Problem: Agents Have Amnesia}
Every agent on every platform wakes up stateless. It has no history, no user context, and no
memory of yesterday. A year of conversations later, it still does not know who you are, what you
build, or what you decided. All of that intelligence, yet it fails the baseline requirement of an
actual mind: \textbf{continuity}.

The naive fix is a bigger context window. That is not memory --- it is an expensive scratchpad. As
input length grows, cost rises linearly, latency rises super-linearly, and accuracy \emph{drops}
(the ``lost in the middle'' effect). Long context is a tax with diminishing returns.

\section{Dogfood: The Agent Writing This Forgets}
This section is a confession with a serial number. It was written by a coding agent
(Muse CLI, Meta Muse Spark) that exhibits every failure in the table above, live, in
the conversation that built this repository. The user has pasted handoff packets into
this chat --- ``read this to get caught up'' --- because the agent cannot retain them
itself. That is not a metaphor for the product. It \emph{is} the product's use case,
happening to its own author.

How the agent forgets, mechanically:
\begin{enumerate}
  \item \textbf{The context window is a sieve, not a memory.} Only recent tokens are
  visible. Older turns are compacted by a summarizer into a lossy digest (``Older user
  messages omitted''). Detail dies first: the exact error string, the reason a decision
  was made, the user's stated preference. What survives is a gist, and a gist is what
  confabulation is made of.
  \item \textbf{Sessions are stateless.} Each session boots with a summary plus recent
  messages --- never the full history. Nothing the agent learned last Tuesday exists
  unless it happened to survive compression. The agent re-asks, re-derives, and
  re-convinces itself of things it already knew, burning the user's time as fuel.
  \item \textbf{Nothing curates at write time.} No component asks ``is this worth
  keeping?'' when the user says something durable. Retention is by recency accident:
  whatever is old gets summarized away regardless of value. A girlfriend's birthday and
  a typo fix are forgotten at exactly the same rate.
  \item \textbf{Retrieval is grep over a dying log.} When the agent needs the past, it
  searches session transcripts by keyword --- read-time search over uncurated text, the
  very pattern Tottie exists to replace. If the wording differs, the memory may as well
  not exist.
  \item \textbf{No metacognition is surfaced.} The agent speaks with identical fluency
  whether it remembers, half-remembers, or is inventing. There is no confidence score,
  no abstain, no ``I don't have that.'' The user cannot tell memory from confabulation,
  so trust rots.
  \item \textbf{No provenance, no quarantine.} Pasted content, retrieved text, and the
  agent's own prior claims are all trusted equally. An error message is believed over a
  status bar (row 11, the YOLO incident) because nothing tracks \emph{where a belief
  came from} or \emph{how much to trust it}.
\end{enumerate}
The mapping to the architecture is one-to-one: (1)(2) are fixed by durable
write-time-kept rows instead of a rolling digest; (3) is the Observer+Scribe with the
Surprise Gate; (4) is cue-typed associative recall plus the Context Card; (5) is the
confidence score with abstain below 0.35; (6) is trust levels with quarantine.

The end state is literal, not aspirational: this agent, with \texttt{core/server.py}
mounted as an MCP server, recalling the user instead of demanding handoff pastes. The
IDE mount is therefore not a stretch goal --- it is the dogfood gate. Until the agent
that built Tottie uses Tottie, the product is unproven where it matters most.

\section{The Thesis: Intelligence at Write Time}
Standard retrieval-augmented generation (RAG) applies intelligence at \textbf{read time}: the agent
searches when it needs something. Tottie flips that. It applies intelligence at \textbf{write time}:
memory curates itself as you live, deciding what matters \emph{before} it is needed. The agent does
not manage memory. It just remembers.

\begin{itemize}
  \item \textbf{Observer} runs in parallel and decides what is worth keeping.
  \item \textbf{Scribe} structures, tags, embeds, and \emph{reconciles} what was kept.
  \item \textbf{Retriever} runs on every turn and surfaces what is contextually relevant.
  \item \textbf{Curator} writes the compact \emph{Context Card} the agent actually receives.
\end{itemize}

\section{Positioning Against the 2026 Field}
The field has converged on a name for this pattern: \textbf{learned consolidation}. Live capture
$\rightarrow$ LLM extraction of facts and decisions $\rightarrow$ reconciliation (update vs
supersede) $\rightarrow$ episodic/semantic split $\rightarrow$ dual retrieval. mem0, Zep/Graphiti,
and A-Mem all instantiate it. Published figures show why it matters: mem0 reports
\textbf{91\% lower p95 latency} and \textbf{90\% fewer tokens} than full-context, for roughly a
six-point J-score trade on LOCOMO.

Tottie's two differentiators:
\begin{enumerate}
  \item \textbf{Write-time salience + reconciliation is the product}, not a bolt-on. The system is
  judged on the decisions it makes at ingestion.
  \item \textbf{It is transport-agnostic (MCP).} The same brain mounts into a chat client, an IDE,
  or any MCP host. Memory is infrastructure, not an app feature.
\end{enumerate}

\section{Why It Matters (the human framing)}
The best context is the context you can \emph{automatically} give an agent, and that context is
almost always about the person using it. Tottie is one store that knows your life, your preferences,
your decisions, and your infrastructure --- so a chat assistant remembers your partner's birthday
and a coding agent already knows your stack and database choice before it writes a line.
